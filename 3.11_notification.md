# 3.11 การทำ Notification

หัวข้อนี้อธิบายระบบ Notification ของโปรเจกต์ โดยอ้างอิงจากโค้ดจริงในระบบเท่านั้น ระบบใช้ LINE Bot / LINE Messaging API สำหรับส่งข้อความแจ้งเตือน เช่น การแจ้งเตือนเมื่อพบชิ้นงาน `NG` และการแจ้งเตือนสถานะ Raspberry Pi Online/Offline

ไฟล์หลักที่เกี่ยวข้องมีดังนี้

- `core/project_config.py` ใช้อ่านค่าการตั้งค่า LINE
- `config.example.json` แสดงตัวอย่างค่าที่ต้องตั้ง
- `app.py` ใช้สร้างข้อความแจ้งเตือนและส่ง LINE Push Message
- `routes/app_routes.py` ใช้รับ Webhook จาก LINE และมี API สำหรับทดสอบสถานะ LINE

## 3.11.1 การตั้งค่า LINE Bot

ระบบอ่านค่าการตั้งค่า LINE จาก environment variable หรือไฟล์ `config.json` ผ่านฟังก์ชัน `get_line_bot_settings()` ในไฟล์ `core/project_config.py`

```python
def get_line_bot_settings():
    cfg = load_local_config()
    return {
        "channel_secret": str(os.getenv("LINE_CHANNEL_SECRET") or cfg.get("LINE_CHANNEL_SECRET") or "").strip(),
        "channel_access_token": str(
            os.getenv("LINE_CHANNEL_ACCESS_TOKEN") or cfg.get("LINE_CHANNEL_ACCESS_TOKEN") or ""
        ).strip(),
        "target_user_id": str(os.getenv("LINE_TARGET_USER_ID") or cfg.get("LINE_TARGET_USER_ID") or "").strip(),
    }
```

ค่าที่ต้องใช้มี 3 ค่า คือ

- `LINE_CHANNEL_SECRET` ใช้ตรวจสอบ signature ของ LINE Webhook
- `LINE_CHANNEL_ACCESS_TOKEN` ใช้เป็น token สำหรับเรียก LINE Messaging API
- `LINE_TARGET_USER_ID` ใช้เป็น user id สำรองสำหรับส่งข้อความแจ้งเตือน

ตัวอย่างค่าจากไฟล์ `config.example.json`

```json
"LINE_TARGET_USER_ID": "replace-with-line-user-id",
"LINE_CHANNEL_ACCESS_TOKEN": "replace-with-line-channel-access-token",
"LINE_CHANNEL_SECRET": "replace-with-line-channel-secret"
```

## 3.11.2 การเชื่อมต่อ LINE Messaging API

ในไฟล์ `app.py` มีฟังก์ชัน `_line_api_request()` สำหรับส่ง request ไปยัง LINE API

```python
def _line_api_request(endpoint, payload):
    settings = get_line_bot_settings()
    access_token = str(settings.get("channel_access_token") or "").strip()
    if not access_token:
        raise ValueError("LINE channel access token is not configured.")

    body = json.dumps(payload).encode("utf-8")
    req = urllib.request.Request(
        endpoint,
        data=body,
        method="POST",
        headers={
            "Content-Type": "application/json",
            "Authorization": f"Bearer {access_token}",
        },
    )
    try:
        with urllib.request.urlopen(req, timeout=15) as resp:
            return resp.status, resp.read().decode("utf-8", errors="replace")
    except urllib.error.HTTPError as exc:
        response_body = exc.read().decode("utf-8", errors="replace")
        raise RuntimeError(f"LINE API failed: HTTP {exc.code} {response_body}") from exc
```

ฟังก์ชันนี้ดึง `channel_access_token` จาก `get_line_bot_settings()` แล้วส่งข้อมูลไปยัง LINE API โดยใส่ token ใน header:

```python
"Authorization": f"Bearer {access_token}"
```

## 3.11.3 การหา User ที่จะรับ Notification

ระบบมีฟังก์ชัน `get_line_alert_recipients()` ในไฟล์ `app.py` สำหรับหา user id ที่จะรับการแจ้งเตือน

```python
def get_line_alert_recipients():
    recipients = []
    try:
        base_url, key = get_supabase_settings()
        select = quote("user_id", safe=",")
        url = f"{base_url}/rest/v1/line_subscribers?select={select}&subscribed=eq.true"
        headers = {"apikey": key, "Authorization": f"Bearer {key}"}
        response = get_json_with_retry(url, headers, timeout=(3.0, 10.0))
        if getattr(response, "status_code", None) == 200:
            parsed = response.json()
            if isinstance(parsed, list):
                recipients = [
                    str(row.get("user_id") or "").strip()
                    for row in parsed
                    if isinstance(row, dict) and str(row.get("user_id") or "").strip()
                ]
    except Exception as exc:
        print(f"[LINE] subscriber lookup failed: {exc}", flush=True)

    if not recipients:
        fallback = str(get_line_bot_settings().get("target_user_id") or "").strip()
        if fallback:
            recipients = [fallback]
    return list(dict.fromkeys(recipients))
```

จากโค้ดนี้ ระบบจะดึงรายชื่อผู้รับจาก Supabase ตาราง `line_subscribers` โดยเลือกเฉพาะแถวที่ `subscribed=eq.true` ถ้าไม่พบผู้รับในตารางนี้ ระบบจะใช้ค่า `LINE_TARGET_USER_ID` จาก config เป็น fallback

ดังนั้นแหล่งข้อมูลของผู้รับ Notification มี 2 แหล่ง คือ

1. ตาราง `line_subscribers` ใน Supabase
2. ค่า `LINE_TARGET_USER_ID` ใน config

## 3.11.4 การส่ง LINE Push Message

ในไฟล์ `app.py` มีฟังก์ชัน `_push_line_messages()` สำหรับส่งข้อความไปยังผู้รับทั้งหมด

```python
def _push_line_messages(messages):
    normalized_messages = [msg for msg in (messages or []) if isinstance(msg, dict)]
    if not normalized_messages:
        raise ValueError("LINE push payload is incomplete.")
    results = []
    for target_user_id in get_line_alert_recipients():
        payload = {
            "to": target_user_id,
            "notificationDisabled": False,
            "messages": normalized_messages,
        }
        results.append(_line_api_request("https://api.line.me/v2/bot/message/push", payload))
    if not results:
        raise ValueError("LINE alert recipients are not configured.")
    return results
```

ฟังก์ชันนี้รับ `messages` ที่เตรียมไว้ แล้ววนส่งไปยัง user id ที่ได้จาก `get_line_alert_recipients()` โดย endpoint ที่ใช้คือ

```python
https://api.line.me/v2/bot/message/push
```

## 3.11.5 LINE Webhook และการรับ Event จาก LINE

ไฟล์ `routes/app_routes.py` มีการตรวจสอบ signature ของ LINE Webhook ด้วย `LINE_CHANNEL_SECRET`

```python
def verify_line_signature(raw_body, signature):
    settings = get_line_settings()
    secret = settings.get("channel_secret") or ""
    if not secret:
        return False
    digest = hmac.new(secret.encode("utf-8"), raw_body, hashlib.sha256).digest()
    expected = __import__("base64").b64encode(digest).decode("utf-8")
    return hmac.compare_digest(expected, str(signature or ""))
```

ระบบมี route สำหรับรับ Webhook จาก LINE ดังนี้

```python
@app.route("/line/webhook", methods=["GET", "POST", "HEAD", "OPTIONS"])
@app.route("/line/webhook/", methods=["GET", "POST", "HEAD", "OPTIONS"])
def line_webhook():
    if request.method in ("GET", "HEAD", "OPTIONS"):
        return jsonify({"success": True, "message": "LINE webhook endpoint ready"})

    raw_body = request.get_data() or b""
    signature = request.headers.get("X-Line-Signature", "")
    settings = get_line_settings()
    if settings.get("channel_secret") and not verify_line_signature(raw_body, signature):
        return jsonify({"success": False, "message": "Invalid signature"}), 403

    payload = request.get_json(silent=True) or {}
    events = payload.get("events") or []
    captured_user_ids = []
    for event in events:
        source = event.get("source") or {}
        user_id = str(source.get("userId") or "").strip()
        if not user_id:
            user_id = ""
        if user_id:
            captured_user_ids.append(user_id)
            try:
                cfg = runtime.load_local_config()
                current_target_user_id = str(cfg.get("LINE_TARGET_USER_ID") or "").strip()
                if not current_target_user_id:
                    cfg["LINE_TARGET_USER_ID"] = user_id
                    runtime.save_local_config(cfg)
            except Exception as exc:
                runtime.log_system_status_sync(f"LINE target user save failed: {exc}")
        try:
            maybe_handle_line_text_command(event)
        except Exception as exc:
            runtime.log_system_status_sync(f"LINE command handling failed: {exc}")

    runtime.log_system_status_sync(f"LINE webhook received {len(events)} event(s)")
    if captured_user_ids:
        runtime.log_system_status_sync(f"LINE target user captured: {captured_user_ids[-1]}")
    return jsonify({"success": True})
```

จากโค้ดนี้ LINE Webhook ทำหน้าที่รับ event จาก LINE ตรวจสอบ signature และดึง `userId` จาก event ถ้ายังไม่มี `LINE_TARGET_USER_ID` ใน config ระบบจะบันทึก user id ที่ได้รับจาก LINE ไว้ใน config

## 3.11.6 คำสั่งที่ผู้ใช้ส่งจาก LINE

ใน `routes/app_routes.py` มีฟังก์ชัน `maybe_handle_line_text_command()` สำหรับอ่านข้อความที่ผู้ใช้ส่งมาทาง LINE

```python
def maybe_handle_line_text_command(event):
    if str(event.get("type") or "").lower() != "message":
        return
    message = event.get("message") or {}
    if str(message.get("type") or "").lower() != "text":
        return

    incoming_text = str(message.get("text") or "").strip().lower()
    reply_token = str(event.get("replyToken") or "").strip()
    if not reply_token:
        return

    if incoming_text.startswith("part "):
        suffix = incoming_text[5:].strip()
        if suffix.isdigit():
            requested_part_id = int(suffix)
            record = fetch_part_record_by_id(requested_part_id)
            if not record:
                reply_line_flex_message(
                    reply_token,
                    f"APE65 A1 PART {requested_part_id} not found",
                    build_part_not_found_flex_message(requested_part_id),
                )
                return
            reply_line_flex_message(
                reply_token,
                f"APE65 A1 PART {requested_part_id}",
                build_now_flex_message(
                    record,
                    title_text="APE65 A1 PART",
                    subtitle_text=f"Inspection record for PART {requested_part_id}",
                ),
            )
            return

    if incoming_text == "status":
        reply_line_flex_message(reply_token, build_status_text(), build_status_flex_message())
    elif incoming_text == "summary":
        reply_line_flex_message(reply_token, build_summary_text(), build_summary_flex_message())
    elif incoming_text == "now":
        reply_line_flex_message(reply_token, build_now_text(), build_now_flex_message())
```

จากโค้ดนี้ ผู้ใช้สามารถส่งคำสั่งผ่าน LINE ได้ เช่น

- `part <id>` เพื่อดูข้อมูลชิ้นงานตาม part id
- `status` เพื่อดูสถานะระบบ
- `summary` เพื่อดูสรุปผล
- `now` เพื่อดูข้อมูลล่าสุด

ข้อมูลที่ใช้ตอบกลับมาจากฟังก์ชันต่าง ๆ เช่น `fetch_part_record_by_id()`, `build_status_flex_message()`, `build_summary_flex_message()` และ `build_now_flex_message()`

## 3.11.8 การส่งแจ้งเตือนเมื่อพบ NG

ฟังก์ชัน `send_ng_alert_async()` ในไฟล์ `app.py` ใช้ส่งแจ้งเตือน NG แบบ background thread

```python
def send_ng_alert_async(session, curr_id, ts, defect_s1, defect_s2, defect_s3):
    def _worker():
        try:
            messages = _build_ng_alert_messages(session, curr_id, ts, defect_s1, defect_s2, defect_s3)
            if not messages:
                return
            _push_line_messages(messages)
            print(f"[LINE] NG alert sent for part {curr_id}", flush=True)
        except Exception as exc:
            print(f"[LINE] NG alert failed for part {curr_id}: {exc}", flush=True)

    threading.Thread(target=_worker, daemon=True).start()
```

ฟังก์ชันนี้สร้างข้อความด้วย `_build_ng_alert_messages()` แล้วส่งผ่าน `_push_line_messages()` โดยทำงานใน thread แยก เพื่อไม่ให้การส่ง LINE ทำให้ระบบตรวจสอบหลักช้าลง

จุดที่เรียกส่ง NG alert อยู่ในฟังก์ชัน `log_part_to_supabase()` ในไฟล์ `app.py`


## 3.11.9 การแจ้งเตือนสถานะ Raspberry Pi Online/Offline

ในไฟล์ `app.py` มีฟังก์ชัน `send_pi_status_alert()` สำหรับส่งสถานะ Online/Offline ของ Raspberry Pi

```python
def send_pi_status_alert(status_text):
    normalized = str(status_text or "").upper().strip()
    now_ts = time.time()
    with _line_pi_alert_lock:
        state = _load_line_pi_alert_state()
        last_status = str(state.get("last_status") or "").upper().strip()
        last_ts = float(state.get("last_ts") or 0.0)
        if normalized == last_status and (now_ts - last_ts) < LINE_PI_ALERT_COOLDOWN_SEC:
            return
        _push_line_flex(
            f"APE65 A1 SYSTEM ALERT Raspberry Pi {normalized}",
            _build_pi_status_alert_flex(normalized),
        )
        _save_line_pi_alert_state({
            "last_status": normalized,
            "last_ts": now_ts,
        })
```

โค้ดนี้ใช้ `_push_line_flex()` ส่งข้อความ Flex Message และมีการเช็ก cooldown เพื่อไม่ให้ส่งแจ้งเตือนสถานะเดิมซ้ำถี่เกินไป

เมื่อระบบเริ่มทำงาน จะเรียก `send_pi_online_alert_async()`

```python
        print(f"[LINE] Raspberry Pi OFFLINE alert failed: {exc}", flush=True)
```

ส่วนที่ผูกกับการเริ่มและหยุดระบบอยู่ท้ายไฟล์ `app.py`

```python
def _handle_shutdown_signal(signum, _frame):
    try:
        send_pi_offline_alert_once()
    finally:
        raise SystemExit(0)

if __name__ == "__main__":
    signal.signal(signal.SIGTERM, _handle_shutdown_signal)
    signal.signal(signal.SIGINT, _handle_shutdown_signal)
    sync_total_parts_from_supabase()
    send_pi_online_alert_async()
```

จากโค้ดนี้ เมื่อโปรแกรมเริ่มทำงานจะส่งแจ้งเตือน `ONLINE` และเมื่อโปรแกรมได้รับ `SIGTERM` หรือ `SIGINT` จะส่งแจ้งเตือน `OFFLINE`

## 3.11.10 API สำหรับตรวจสอบและทดสอบ LINE

ในไฟล์ `routes/app_routes.py` มี API สำหรับตรวจสอบว่า LINE ถูกตั้งค่าแล้วหรือไม่

```python
@app.route("/api/line/status")
def api_line_status():
    settings = get_line_settings()
    return jsonify({
        "success": True,
        "line_configured": bool(settings.get("channel_secret") and settings.get("channel_access_token")),

        "has_channel_access_token": bool(settings.get("channel_access_token")),
        "has_target_user_id": bool(settings.get("target_user_id")),
```

และมี API สำหรับทดสอบส่งข้อความ LINE

```python
@app.route("/api/line/test_send", methods=["POST"])
```

## 3.11.11 สรุปการทำงานของ Notification

ลำดับการทำงานของระบบ Notification จากโค้ดจริงสามารถสรุปได้ดังนี้

```text
ตั้งค่า LINE_CHANNEL_SECRET, LINE_CHANNEL_ACCESS_TOKEN, LINE_TARGET_USER_ID
→ ระบบอ่านค่าผ่าน get_line_bot_settings()
→ LINE Webhook รับ event จากผู้ใช้และบันทึก userId ลง config ถ้ายังไม่มี
→ เมื่อระบบตรวจพบชิ้นงาน NG และบันทึกผลลง Supabase สำเร็จ
→ ระบบสร้าง Flex Message จากข้อมูล part_session, defect, capture URL และ dimension
→ ระบบหา recipient จาก Supabase line_subscribers หรือ fallback เป็น LINE_TARGET_USER_ID
→ ส่งข้อความผ่าน LINE Messaging API endpoint /v2/bot/message/push
```

แหล่งข้อมูลที่ใช้ใน Notification คือ

- ค่าเชื่อมต่อ LINE จาก `config.json` หรือ environment variable
- รายชื่อผู้รับจาก Supabase ตาราง `line_subscribers`
- ข้อมูลผลตรวจชิ้นงานจาก `session`
- ข้อมูล defect จาก `defect_s1`, `defect_s2`, `defect_s3`
- รูปภาพจาก `capture_s1`, `capture_s2`, `capture_s3`
- ค่าการวัด SIDE 3 จาก `dimension_top`, `dimension_bottom`, `dimension_length`
- สถานะระบบ Online/Offline จากการเริ่มและหยุดโปรแกรม
